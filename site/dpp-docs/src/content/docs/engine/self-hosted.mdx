title: Self-hosting
description: Run a node on your own infrastructure with the odal CLI. Your keys and your data stay with you; only the signed passport is published.

Self-hosting is the standard way to run Odal Node. You run the engine on infrastructure you control, with your own keys. There are no licence keys, no passport caps, and no features held back for payment. Production self-hosting for your own organisation is free under the engine's licence.

## What you need

Docker and the `odal` CLI. The node and resolver are published as container images (`ghcr.io/odal-node/dpp-node` and `dpp-resolver`), each with a software bill of materials and build provenance attached; you only need a clone of the engine repository to build from source.

## The steps

1. **Configure your secrets.** The node fails closed without them. Database credentials, a key-store passphrase and your admin login go in a local environment file you create.
2. **Bring it up.** Running `odal` walks you through it: it starts the node, then onboards you and mints your first API key. Outside a clone, `odal up` pulls the published images; inside one, it builds from source, which takes a few minutes the first time.
3. **Check its health.** `odal status` confirms the node is up and serving, and shows which of its services are real and which are stand-ins.
4. **Go live carefully.** [Production deployment](/engine/deployment) covers TLS, the two public addresses and the checks to run first, and [Backup, restore and key custody](/engine/backup) covers what to protect.

The [Quick Start](/quick-start) is the short version of these steps.

## What stays with you

Your signing key is generated and held on your own infrastructure, encrypted at rest, and never leaves it. Your import files are discarded after signing. What remains is the signed passport (the full product data you published, its history and the metadata needed to serve it) and a record of what each import found, row by row. This holds whoever operates the node; see [What Odal can and cannot see](/getting-started/what-odal-can-and-cannot-see).

## Keeping current

The engine and the product-group rules change as the regulation does. `odal update` pulls the latest images, with the latest product-group schemas and fixes, and a new signed plugin can be installed on a running node with `odal plugin install`. A node you never update keeps working, but falls behind the regulation over time.
